Session 2 - Test Structure, Commands and Assertions

Goal: Move students from “running Cypress” to “writing useful tests”

Concept 1 - Cypress Test Structure

describe()

Used to group related test cases into one test suite.

it()

Represents a single test case or scenario.

cy

The Cypress object used to perform actions like visit, click, type and verify.

Example

describe('Login Page Tests', () => { it('should open the login page', () => { cy.visit('https://example.cypress.io') }) })

Concept 2 - Core Commands

cy.visit(url)

Opens a page or application.

cy.get(selector)

Selects an element using a CSS selector.

cy.contains(text)

Finds an element using visible text.

cy.type()

Types into a textbox or textarea.

cy.click()

Clicks a button, link or other clickable element.

cy.clear()

Clears an input field before entering a new value.

Example

cy.visit('https://example.cypress.io/commands/actions') cy.get('.action-email') .type('student@test.com') cy.get('.action-email') .clear() .type('cypress@test.com') cy.contains('Submit').click()

Concept 3 - Assertions

Assertions help us verify that the application behaves as expected.

be.visible

Checks whether an element is visible on the page.

exist

Checks whether the element exists in the DOM.

contain

Checks whether an element contains some text.

have.value

Checks the current value inside an input field.

Assertion Examples

cy.get('.action-email').should('be.visible') cy.get('.action-email').should('have.value', 'cypress@test.com') cy.contains('Email').should('exist') cy.get('button').should('contain', 'Submit')

describe('Cypress Session 2 Demo', () => { it('should type into a textbox and verify the value', () => { cy.visit('https://example.cypress.io/commands/actions') cy.get('.action-email') .type('student@test.com') .should('have.value', 'student@test.com') cy.get('.action-email') .clear() .type('hello@cypress.com') .should('have.value', 'hello@cypress.com') }) })

Concept 1 - Understanding Selectors

Cypress usually finds elements using cy.get(). To use cy.get() properly, students must understand selectors.

ID Selector

#email selects an element whose id is email.

Class Selector

.btn-primary selects elements with that CSS class.

Tag Selector

button selects all button elements.

Attribute Selector

[type="checkbox"] or [name="gender"] selects based on attributes.

Examples of Selectors

cy.get('#email') cy.get('.login-btn') cy.get('button') cy.get('[type="checkbox"]') cy.get('[name="gender"]') cy.get('select')
Teaching point: explain that selectors are how Cypress identifies elements on the page. A test becomes easier to maintain when selectors are clear and stable.

Concept 2 - Working with Buttons

Buttons are the most common clickable elements in UI testing.

Click a button

Use .click() to press a button.

Find by text

Use cy.contains('Submit') if the button text is visible.

Verify button text

Use .should('contain', 'Submit').

Example

cy.contains('Submit').click() cy.get('button').should('contain', 'Submit')

Concept 3 - Working with Checkboxes

Checkboxes are used when the user can select one or more options.

.check()

Selects a checkbox.

.uncheck()

Removes the selection from a checkbox.

be.checked

Assertion to verify that the checkbox is selected.

Example

cy.get('[type="checkbox"]').first().check().should('be.checked') cy.get('[type="checkbox"]').first().uncheck().should('not.be.checked')

Concept 4 - Working with Radio Buttons

Radio buttons allow the user to select only one option from a group.

Select a radio option

Use .check() on the specific radio input.

Verify selection

Use .should('be.checked').

Example

cy.get('[type="radio"]').first().check().should('be.checked')

Concept 5 - Working with Dropdowns

Dropdowns are usually tested using the .select() command.

.select()

Selects an option from a dropdown.

Verify value

Use .should('have.value', '...') to confirm the selected option.

Example

cy.get('select').select('apples') cy.get('select').should('have.value', '456')
The value used in have.value depends on the actual HTML option value in the page.

Concept 6 - beforeEach()

In many test suites, every test needs the same starting step such as opening the same page. Instead of repeating that code inside every it(), Cypress provides beforeEach().

Why use it?

It avoids repetition and keeps the test file cleaner.

When does it run?

It runs before every test case inside the current test suite.

Example

describe('Form Control Tests', () => { beforeEach(() => { cy.visit('https://example.cypress.io/commands/actions') }) it('should type into textbox', () => { cy.get('.action-email') .type('student@test.com') .should('have.value', 'student@test.com') }) it('should click a button', () => { cy.contains('Submit').click() }) })

Session 3 - Full Demo Test Suite

This demo combines selectors, form controls and beforeEach().

describe('Cypress Session 3 Demo', () => { beforeEach(() => { cy.visit('https://example.cypress.io/commands/actions') }) it('should type in textbox and verify value', () => { cy.get('.action-email') .type('trainer@test.com') .should('have.value', 'trainer@test.com') }) it('should check and uncheck a checkbox', () => { cy.get('.action-checkboxes [type="checkbox"]') .first() .check() .should('be.checked') cy.get('.action-checkboxes [type="checkbox"]') .first() .uncheck() .should('not.be.checked') }) it('should select a radio button', () => { cy.get('.action-radios [type="radio"]') .first() .check() .should('be.checked') }) it('should select a value from dropdown', () => { cy.get('.action-select') .select('apples') }) })
