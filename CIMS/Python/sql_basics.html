SQL Advanced Concepts

This page gives a quick round-up of five important SQL concepts: Stored Procedures, Triggers, Cursors, Subqueries, and Views.

1) Stored Procedure (SP)

Definition: A Stored Procedure is a pre-written block of SQL statements stored in the database and executed whenever needed.

Why use it?

  • Reusability of SQL code
  • Improves maintainability
  • Can accept parameters
  • Used for insert, update, delete, select operations

Example: Stored Procedure to display all employees

CREATE TABLE Employees (
    EmpID INT PRIMARY KEY,
    EmpName VARCHAR(50),
    Salary INT
);

INSERT INTO Employees VALUES
(1, 'Amit', 25000),
(2, 'Neha', 40000),
(3, 'Ravi', 30000);

CREATE PROCEDURE GetAllEmployees
AS
BEGIN
    SELECT * FROM Employees;
END;

EXEC GetAllEmployees;

Procedure with Parameter:

CREATE PROCEDURE GetEmployeeById
    @id INT
AS
BEGIN
    SELECT * FROM Employees
    WHERE EmpID = @id;
END;

EXEC GetEmployeeById 2;
Exam line: A Stored Procedure is a named collection of SQL statements stored in the database and executed as a unit.

2) Trigger

Definition: A Trigger is a special SQL block that runs automatically when an event like INSERT, UPDATE, or DELETE happens on a table.

Why use it?

  • Automatic actions after data changes
  • Audit logging
  • Validation and business rules

Example: Trigger after inserting an employee

CREATE TRIGGER trg_AfterInsertEmployee
ON Employees
AFTER INSERT
AS
BEGIN
    PRINT 'New employee inserted successfully!';
END;

INSERT INTO Employees VALUES (4, 'Sneha', 50000);

Using inserted table:

CREATE TRIGGER trg_ShowInsertedEmployee
ON Employees
AFTER INSERT
AS
BEGIN
    SELECT * FROM inserted;
END;

Special tables in triggers:

  • inserted → contains newly inserted rows
  • deleted → contains deleted rows or old rows before update
Exam line: A Trigger is a database object that executes automatically when a specified event occurs on a table.

3) Cursor

Definition: A Cursor is used to process query results one row at a time.

Why use it?

  • When row-by-row processing is needed
  • Useful for custom logic on each record
  • Not preferred when set-based SQL can solve the problem

Cursor Steps:

  1. Declare cursor
  2. Open cursor
  3. Fetch rows
  4. Process rows
  5. Close cursor
  6. Deallocate cursor

Example: Display employee names one by one

DECLARE @name VARCHAR(50);

DECLARE emp_cursor CURSOR FOR
SELECT EmpName FROM Employees;

OPEN emp_cursor;

FETCH NEXT FROM emp_cursor INTO @name;

WHILE @@FETCH_STATUS = 0
BEGIN
    PRINT @name;
    FETCH NEXT FROM emp_cursor INTO @name;
END;

CLOSE emp_cursor;
DEALLOCATE emp_cursor;
Exam line: A Cursor is a database object used to fetch and process rows one at a time from a result set.

4) Subquery

Definition: A Subquery is a query written inside another query.

Why use it?

  • To get intermediate values for the main query
  • To compare with aggregate values like AVG, MAX, MIN
  • To simplify complex SQL conditions

Example 1: Employees with salary greater than average salary

SELECT EmpName, Salary
FROM Employees
WHERE Salary > (
    SELECT AVG(Salary) FROM Employees
);

Example 2: Employee with maximum salary

SELECT EmpName, Salary
FROM Employees
WHERE Salary = (
    SELECT MAX(Salary) FROM Employees
);

Types of Subqueries:

  • Single-row subquery
  • Multiple-row subquery
  • Nested subquery
Exam line: A Subquery is a query inside another SQL query used to return data for the main query.

5) View

Definition: A View is a virtual table created from a SQL query. It does not store data separately; it shows data from one or more tables.

Why use it?

  • Hide complex queries
  • Provide security by exposing only required columns
  • Reuse common SELECT queries

Example: Create a view to show employee names and salary

CREATE VIEW EmployeeView AS
SELECT EmpName, Salary
FROM Employees;

SELECT * FROM EmployeeView;

Another example: View for high-salary employees

CREATE VIEW HighSalaryEmployees AS
SELECT EmpID, EmpName, Salary
FROM Employees
WHERE Salary > 30000;
Exam line: A View is a virtual table based on the result of a SQL query.

6) Quick Comparison

Concept Purpose Runs How?
Stored Procedure Store reusable SQL logic Executed manually using EXEC
Trigger Automatic action on INSERT/UPDATE/DELETE Runs automatically
Cursor Process rows one by one Manual row-by-row processing
Subquery Query inside another query Runs as part of main query
View Virtual table from a query Used like a table in SELECT

7) Final Summary

  • Stored Procedure → saved SQL program
  • Trigger → automatic action on table event
  • Cursor → row-by-row processing
  • Subquery → query inside another query
  • View → virtual table created from a query
